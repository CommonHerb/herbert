# Herbert roadmap

Herbert's direction is a sovereign computing stack: a small mother language,
one compiler backend, and source-authored layers that eventually run the
compiler on Herbert's own operating system. Ambition has no size cap. Each
piece must remain understandable and verifiable on demand.

## What exists

- A self-hosting Linux/x86-64 compiler, distributed as a committed native seed.
  Its own source compiles back to the same bytes without a foreign compiler.
- Hosted arithmetic, recursion, tuples, collections and process I/O. The checked
  input and compiler publication contracts are documented in `README.md`.
- A useful hosted [word counter](examples/wordcount.md) exercising checked input
  and sustained processing without per-byte allocations or growing stack use.
- A source-authored long64 kernel path with boot, device input/output, tail calls
  and guarded indexed memory. Its supported language surface is narrower than
  hosted Herbert; it is not a complete OS or a general memory-safe runtime.
- A [streaming counter](examples/wordcount_long64.md) runs on that long64 path,
  using fixed guest memory and an explicit serial end-of-input protocol. A host
  adapter supplies bytes; the guest performs all counting and decimal output.
- A [binary file viewer](examples/hexview_long64.md) consumes one raw boot module
  through `boot_read()`, with stable EOF and a fully reserved image/stack range.
  The file is read in place; the guest renders its contents as hexadecimal.
- An [ELF inspector](examples/elfinfo_long64.md) uses that same input provider to
  report the compiler's and its own executable headers. Parsing and formatting
  run in Herbert; the existing host adapter carries only bytes and completion.
- Earlier kernel experiments, including frozen Python-generated byte blobs,
  remain reference and verification material. They do not count as newly
  source-authored Herbert capability.

## What progress should address next

Use concrete programs to choose the next missing facility. The compiler itself
is the eventual integration program: it needs process entry/exit, sufficient
memory, input through EOF, named file output and diagnostics on the sovereign
long64 target. Each facility must compose with the layer below it and serve a
real program before a larger layer depends on it.

The counters, file viewer and executable inspector exercise today's facilities.
The serial protocol supplies logical stream completion; boot input supplies
finite module bytes and EOF without a serial sender. Neither is a filesystem.
Neither counter solves unequal-width mutual tail calls or heap reclamation.
A program with bounded live data and sustained allocation should drive lifetime
or reclamation work when that becomes the next actual blocker. Avoid growing
features or test infrastructure merely to increase a count.

## How progress is judged

`VERIFYING.md` describes the existing gates and their limits. Keep the tests tied
to a concrete behavior or demonstrated failure; consolidate duplicate machinery
and stop expanding a test matrix once it establishes the needed property.
Preserve the self-hosting fixpoint, meaningful independent oracles, byte pins,
and runtime observations. A model verdict cannot replace those observations.

CI separates hosted checks from kernel groups and retains actual failed
attempts. Kernel claims require the applicable independent emulator and local
hardware checks, with missing required tooling treated as a failure. A passing
subset must never be described as a passing complete stack.

The `BOOTSTRAP-ALLOWLIST` makes foreign tooling visible. Retire a tool when a
verified Herbert replacement is useful; a lower file count by itself is not
sovereignty. The C bootstrap interpreter remains retired. Frozen C-derived
artifacts and the seed's original minting provenance remain explicit trust
anchors; reproducing a seed establishes consistency, not independent provenance.

Current decisions and open debts live in the MEWTWO canon one repository up.
Historical responsibility details remain in `BOOTSTRAP-RESPONSIBILITIES.md`.
